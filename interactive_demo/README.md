# Standalone interactive GRLP demo (experimental)

A browser-based, slider-driven demo of a single gravel-bed river responding to
its **water input**, **sediment input**, and **base level** — GRLP running
entirely in your browser via Pyodide / JupyterLite. It is deliberately kept
**out of the ReadTheDocs site** for now: standalone, until it has been tested
enough.

## Run it

One-time toolchain install:

```sh
pip install jupyterlite-core jupyterlite-pyodide-kernel
```

Then:

```sh
./run_demo.sh
```

This builds the GRLP wheel, points JupyterLite's installer at it, and serves the
site (Pyodide downloads on first run). In the browser tab that opens, open
`interactive_single_segment.ipynb`, run all cells, and drag the sliders.

## What to check (test checklist)

- [ ] `%pip install grlp networkx` resolves (GRLP from the bundled wheel).
- [ ] The three sliders (Water Q, Sediment Qs, Base level) redraw the profile.
- [ ] Response is smooth (target < ~1 s/update; native compute is ~9 ms).
- [ ] Lane's balance reads correctly: more sediment → steeper; more water →
      gentler; lower base level → the profile drops.

## Files

- `interactive_single_segment.ipynb` — the demo (sliders + GRLP compute).
- `run_demo.sh` — build the wheel + launch JupyterLite.
- `jupyter_lite_config.json` — generated by `run_demo.sh` (wheelhouse config).
- `pypi/`, `_output/`, `.jupyterlite.doit.db` — build artifacts (git-ignored).

## Status / notes

- **Verified natively:** the compute logic (correct Lane's-balance response,
  ~9 ms/update) and the pure-Python `grlp` wheel. **Not yet verified:** the
  in-browser (WASM) execution and slider responsiveness — that is what this
  standalone package is for.
- If `%pip install grlp` does not resolve from the wheelhouse, install by wheel
  URL in the notebook, or adjust `piplite_urls` in `jupyter_lite_config.json`.
- Once tested and trusted, the route to embed this in RTD is `jupyterlite-sphinx`
  (a `{jupyterlite}`/`{voici}` directive). We are intentionally not doing that
  yet.
